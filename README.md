# Лисий диспетчер

Интерактивное мини-приложение для анализа наблюдений за лисами в волшебном лесу. Один HTML-файл, без сборки и зависимостей.

Онлайн-версия: https://foxes-lake.vercel.app/


## Какой сценарий выбран

**«Лисий диспетчер»** — инструмент лесного смотрителя для анализа наблюдений за лисами.

Пользователь — не аналитик, а человек в поле: ему нужно быстро понять текущую ситуацию и получить одну рекомендацию, а не изучать дашборд. Отсюда логика экрана:

- **Наблюдения** — таблица со всеми записями, редактируемая прямо на месте: можно поправить подозрительность, локацию, отметку о добыче.
- **Фильтры и веса** — локация, цвет, наличие добычи, минимальный уровень подозрительности; ползунками настраиваются вес подозрительности, бонус за добычу и бонус за повторные появления.
- **Метрики** — количество наблюдений в выборке, уникальные лисы, самая активная локация.
- **Карта активности** — подсветка точки с наибольшим числом наблюдений по текущей выборке.
- **Рейтинг подозрительности** — лисы, отсортированные по score, у каждой текстовое объяснение, из чего сложилось число.
- **Отчёт смены** — готовый абзац текста: где активность, кто подозрительнее всех, что делать дальше.

Формула score намеренно линейная и читаемая:

```
score = средняя подозрительность × вес
      + количество появлений с добычей × бонус за добычу
      + повторные появления × бонус за повторы
```

Ключевое свойство прототипа: любое изменение — фильтр, ползунок, правка ячейки, добавление или удаление записи — мгновенно пересчитывает все блоки сразу. Видно не только результат, но и то, как он зависит от параметров.

Дополнительно: загрузка своего набора наблюдений через JSON с валидацией, добавление записи через форму, сброс фильтров и сброс данных к исходным.

## Стек

- **HTML + CSS + vanilla JavaScript** — один файл `index.html`, ~2000 строк.
- **Ноль зависимостей**: без фреймворков, без сборщика, без CDN, без бэкенда. Карта — инлайновый SVG, шрифты системные.
- **Архитектура**: одно состояние `state` → чистые функции расчёта (`filterObservations`, `calculateFoxRanking`, `buildReport`) → единый `render()`. Никакой реактивности, логику можно прочитать сверху вниз.
- **Данные** живут в JS-состоянии, персистентность не используется — перезагрузка страницы возвращает исходный набор.

Почему так: тестовое должно открываться двойным кликом и проверяться за минуту, а не через `npm install`. React + Vite дали бы компонентность, но добавили бы сборку ради пяти блоков экрана — не окупается.

## AI-инструменты и проверка результата

**Что использовала:** Claude Code (Opus 4.8) в VS Code — как основной инструмент для написания и доработки кода. Работала в режиме «от документа»: сначала PRD (`PRD_Лисий_диспетчер.md`), потом реализация по нему.

**Как строила работу:** PRD как единый источник требований → отдельный заход на структуру экрана и архитектуру кода до написания логики → итерации по конкретным недостаткам. Формулу score и вынос весов в интерфейс определяла сама; после ответов AI поменяла сортировку рейтинга на детерминированную и пересчёт повторных появлений.

**Как проверяла:** руками в браузере по списку сценариев, каждый раз сверяя четыре блока одновременно — метрики, карту, рейтинг и текст отчёта:

- стартовые данные из задания — сверила с ручным пересчётом формулы;
- фильтры до пустой выборки — корректное пустое состояние, чисто в консоли;
- битый JSON, JSON не массивом, запись без поля, `suspicion_level` = 15, время `25:00`, дублирующиеся id — каждый случай даёт конкретное сообщение с номером записи;
- крайние значения весов (0 и максимум) — лидер меняется предсказуемо, объяснение соответствует новым числам;
- добавление, редактирование, удаление наблюдения — все производные блоки пересчитываются согласованно;
- сброс фильтров и сброс данных возвращают исходное состояние;
- финальная сверка файла с разделом требований PRD построчно.

**Что нашла и починила по ходу:** пропуск дублирующихся id при загрузке JSON, отсутствие приведения типов у входящих данных, падение расчёта на пустой выборке, вставку пользовательских строк в разметку без экранирования, «3 наблюдение» вместо «3 наблюдения» в отчёте, нестабильный порядок рейтинга при равных score.

Полная версия истории работы с AI — прямо в приложении, блок «AI Worklog» внизу страницы.
